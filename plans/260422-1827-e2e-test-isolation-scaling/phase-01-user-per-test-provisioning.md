# Phase 01 — User-per-test Provisioning

**Priority**: High (foundational — all other phases depend on this)
**Status**: Todo

## Overview

Pre-provision one dedicated James user per test scenario during the single Docker startup. Tests are assigned their own namespace — no data bleeds between them, zero teardown cost for the majority of tests.

## Key Insight

The backend image is `memory-*` — all data is in RAM. Container restart wipes all data. Provisioning at startup is the ONLY cheap time to create users. We batch-create N users once rather than restart per test.

## Requirements

- Each test scenario gets a stable, deterministic user email (e.g. `test_001@example.com`)
- Users needing pre-loaded EML data have those emails imported at provisioning time (not per-test)
- `USERNAME` / `BASIC_AUTH_EMAIL` dart-defines become per-test, not global
- Provisioning must stay under 3 minutes for 500 users (james-cli is fast)

## User Assignment Strategy

Use a deterministic index approach — each test file maps to a slot:

```
integration_test/tests/composer/send_email_test.dart    → slot 001
integration_test/tests/composer/draft_email_test.dart   → slot 002
integration_test/tests/thread/open_email_test.dart      → slot 003
...
```

Slots are assigned at provisioning time and read back via a generated env file that patrol sources.

```bash
# Generated by provisioning step:
# integration_test/test_user_map.env
TEST_SEND_EMAIL_USER=test_001@example.com
TEST_DRAFT_EMAIL_USER=test_002@example.com
...
```

Or simpler — pass `TEST_USER_INDEX` as dart-define; test computes its own address:
```dart
static String get testEmail =>
  'test_${const String.fromEnvironment('TEST_USER_INDEX', defaultValue: '001')}@example.com';
```

## Implementation Steps

1. **Audit existing tests** — list which scenarios need pre-loaded EML (search order, forward, reply chain, calendar, base64 image)
2. **Update `provisioning.sh`**:
   - Accept `NUM_USERS` env var (default: 10 for local, set per shard in CI)
   - Create `test_001` through `test_NNN` users
   - For slots that need EML: import the correct `.eml` file per user at provisioning
   - Example structure:
     ```bash
     NUM_USERS=${NUM_USERS:-10}
     for i in $(seq -w 1 $NUM_USERS); do
       james-cli AddUser "test_$i@example.com" "test_$i"
     done
     # EML imports for known slots
     james-cli ImportEml \#private "test_001@example.com" "INBOX" "/root/conf/integration_test/eml/..."
     ```
3. **Update run scripts** — set `NUM_USERS` to match shard test count; export `TEST_USER_INDEX` range per shard
4. **Update `TestBase.runPatrolTest()`** — accept optional `userIndex` param; pass correct `USERNAME` / `BASIC_AUTH_EMAIL` to the scenario
5. **Update `BaseTestScenario`** — read user from dart-define with index suffix

## Acceptance Criteria

- [ ] 500 users provisioned in < 3 minutes
- [ ] Each test scenario receives a unique `@example.com` user credential
- [ ] Pre-loaded EML tests pass with per-user imported data
- [ ] Mobile CI green, Web CI green after change

## Risk

| Risk | Mitigation |
|------|------------|
| Test-to-slot mapping breaks on file rename | Use filename hash as stable slot key; document in ADR |
| EML slot mapping grows complex | Keep a `provisioning_slot_map.sh` lookup table alongside provisioning.sh |
| james-cli rate limits under 500 concurrent calls | Use sequential loop with no sleep — james-cli is local exec, no HTTP rate limit |
